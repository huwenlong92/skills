# sdenv 数据库与基础服务

核心能力是通过 sdenv 使用 Docker context 中的数据库与基础服务：定位环境和服务、查询数据与结构、执行获准的备份恢复，以及排查连接问题。安装发现、配置读取和命令帮助为这些任务提供依据。

已安装的 sdenv 包含完整源码、配置与说明，是当前环境的权威来源。禁止维护另一份安装路径、主机地址、容器名称或服务版本清单。

## 任务分流

| 任务 | 必须读取 |
|---|---|
| Docker context 中的数据库与基础服务：查询数据、检查表结构、备份恢复、Redis/NATS 操作或连接排查 | [安装发现与配置读取](references/discovery.md)、[服务入口与操作边界](references/services.md) |
| 单独定位安装、配置或模块；排查 shell 命令未加载 | [安装发现与配置读取](references/discovery.md) |

## 执行顺序

1. 根据当前用户要求或目标项目声明判断是否使用 sdenv。已有明确 sdenv 约定时，数据库与基础服务任务必须沿用该入口；禁止每次重新询问是否使用 sdenv。没有依据时，不能只因安装了本 skill 而改换项目环境。
2. 动态发现当前生效的安装根目录，读取其根说明和命中模块的配置、README 与帮助；禁止把私有源码或配置复制进 skill。
3. 服务任务必须按服务 reference 确定目标场景、实际 Docker context、服务版本及数据库或资源范围；禁止找到安装目录后就把定位任务视为完成。
4. 落实服务 reference 的授权与验证门禁，通过已安装版本提供的入口完成当前任务；函数未加载时按发现 reference 临时加载，禁止安装宿主机客户端来掩盖入口问题。
5. 分别报告实际服务操作结果与验证；不能把帮助可读、context 存在或命令可调用描述为数据查询、备份恢复已经完成。

## 共同门禁

- 当前用户要求 > 目标项目显式规则 > 本 skill > 历史实现。安装目录中的说明只用于当前 sdenv 环境，不构成修改其他仓库、生产数据或部署的授权。
- 禁止在 skill 中写入私有库地址、机器路径、凭据或安装配置快照。安装完整源码已提供说明时，必须读取命中说明，禁止另建技能专用机器配置机制。
- 发现安装只授权读取路径、说明和当前任务需要的配置，不授权更新 sdenv、修改 shell 配置、写配置或连接服务。
- 安装无法定位、出现无法解释的多安装冲突或必要配置缺失时，停止依赖该信息的操作并说明缺口；禁止猜测服务器或自动安装环境。
