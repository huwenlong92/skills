# DockerOps

让 Dockerfile 消费镜像库中已发布的基础镜像与共享 builder，缺少时补齐镜像库。禁止将当前镜像清单复制进本 skill。

本 skill 只负责镜像选择与接入、镜像同步和 builder 发布；不负责业务容器部署、启停、重启或资源清理。

## 任务分流

| 任务 | 必须读取 |
|---|---|
| 生成、修改或评审 Dockerfile；查询镜像；选择基础镜像或 builder | [镜像选择与接入](references/selection.md) |
| 镜像、版本线缺失，发布记录不完整，或需要新增/升级 builder | [镜像选择与接入](references/selection.md)、[同步与发布](references/publication.md) |

## 执行顺序

1. 读取消费项目的显式规则、Dockerfile 和版本声明，确定工具链、系统变体、构建/运行阶段及业务目标架构。
2. 按选择 reference 解析镜像库位置。读取镜像库 `AGENTS.md`（存在时）、`README.md`、`images.txt`，只加载匹配的配置、配方与发布记录。
3. 用 [只读清单工具](scripts/catalog.py) 查询最新记录；静态记录不能证明远端可用，选中后必须执行对应远端验证。
4. 已有匹配发布则接入；缺失或记录异常则进入发布 reference，遵守当前用户与镜像库的明确授权。禁止用不兼容版本凑数。
5. 完成 Dockerfile 与必要关联引用的修改，执行与任务范围匹配的验证，交付消费地址、架构和验证结果。

## 共同门禁

- 用户当前要求 > 目标项目显式规则 > 本 skill > 历史实现。用户明确指定其他镜像来源时必须遵守，禁止强行改为 Mirror。
- 镜像库的普通与回滚/唯一版本标签必须支持 `linux/amd64`、`linux/arm64`。业务只要求 amd64 时，必须保持业务 amd64 打包；基础镜像双架构不构成扩大业务构建范围的授权。
- 镜像同步、builder 发布、Git 提交/推送和业务部署的授权分别判断。仅在当前用户或目标镜像库显式规则已经授权时执行对应操作，禁止把其他仓库的持续授权移植过来。
- 使用执行主机既有认证，禁止记录或输出密码、Token、私钥及 Docker 认证配置。禁止因镜像接入而触发业务 Webhook、服务器更新或数据操作。
- 只修改本次 Dockerfile 接入与缺失镜像所需文件。禁止顺带升级工具链、批量同步全库、删除旧标签或提交无关改动。
- 自动发现只在 agent 已加载本技能时成立；安装不代表每轮一定触发，也不替代真实发布与构建验收。
