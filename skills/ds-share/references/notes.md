# 笔记与知识库

适用范围：用户要求将分享整理成笔记、归档或同步知识库。必须先按[分享读取](read-share.md)取得并复核材料；仅要求阅读或总结时禁止自动写入。

## 写入前提与位置

- 必须从用户要求、目标项目声明或当前会话明确规则确定知识库，读取目标根目录 AGENTS.md 与命中分类规则；禁止依赖本机固定目录或新建未经指定的知识库。
- 必须先搜索已有同主题内容。同主题且可增量合并时必须更新原笔记；只有目标主题独立或规则要求拆分时才允许新建，并更新相关索引。
- 笔记正文与附件只允许写入目标知识库规则明确允许的位置；禁止写工具配置目录、技能源目录或默认把原始 JSON 保存为长期附件。
- 未确定目的地时允许在对话交付笔记草稿，禁止猜测文件路径。写入、发布与分享权限分别判断，授权入库不代表允许公开发布。

## 笔记内容

- 必须保留原分享 URL，并区分用户原始意图、DeepSeek 的建议和当前 Agent 的分析；禁止把对话角色合并成无来源结论。
- 必须提炼可复用方法、适用条件、已确认决策与未解决项。用户明确要求完整归档时允许保留全部公开正文并标明角色；禁止不经整理把全部原始 JSON 当成成品笔记。
- 涉及当前产品、API、政策或技术事实时，必须按任务需要用官方资料或一手证据核验；无法核验时标为待确认，禁止把 DeepSeek 回答本身作为事实依据。
- 原始材料存在敏感信息时必须脱敏，禁止把凭据、Token、私钥、密码和非公开连接串写进长期笔记、附件或共享 skill。
- 只取得摘要或部分正文时必须写明缺失范围，并采用目标知识库的草稿状态；没有约定时使用 status: draft，禁止标记为完整或已验证。未读附件不能因正文已读完而被标为已归档。

以下是脱敏笔记形态；metadata 与章节必须服从目标知识库规则：

```md
来源：https://chat.deepseek.com/share/example_share_id
材料范围：已读该分享返回的正文；附件尚未读取。

## 用户问题与适用场景
## 对话给出的方案
## 核验与补充分析
## 可复用步骤
## 未确认事项与缺失材料
```

反例：移除来源、将助手建议写成已验证事实，或在仅有摘要时把笔记标记为完整。

## 完成标准

- 写入得到用户授权，目的地与分类符合已读取规则；已搜索重复内容并保留来源。
- 已分清角色、事实核验和当前分析；敏感信息已脱敏，未取得材料与待确认结论明确。
- 必须检查正文/附件相对链接与必要索引，交付实际笔记路径和已写入范围。
- 人工检查总结是否覆盖已读正文，是否把局部材料误写成完整会话；受阻时必须明确未写入的部分。
