# Vab 性能测量与高频副作用

适用范围：修改完整 Vab 模板的首屏、分包、公共布局 resize/scroll、缓存与资源发布策略时必须读取。必须同时读取 [框架边界](framework.md)；禁止把本规范套入 Admin Lite，禁止借优化重做界面、授权或依赖升级。

## 测量与分包

- 必须先区分首屏网络、菜单异步依赖、主线程与服务器开销；必须保留相同依赖、构建模式、环境与压缩算法的基线，再做局部修改。
- 首屏体积必须按入口递归静态 imports 去重统计；场景必需的动态布局/登录页必须补计，普通路由动态 imports 单独列出。必须分别报告 JS/CSS、原始字节、压缩字节和请求数，禁止用整个 dist 或最大异步文件代表首屏。
- manualChunks 必须依据实际依赖图决定；禁止默认把 Element Plus 全部合并公共 chunk 或推导成所有项目都删除分组。只允许保留经入口、典型路由、缓存、请求数及运行错误验证有效的改动。
- gzip 只减少传输，不能证明解析、执行、交互开销下降；禁止把体积下降比例写成用户耗时收益。

## 高频回调

- 创建 listener/watch 的组合式 API 必须在 setup 初始化一次后复用，禁止每次 resize/scroll 调用 `useWindowSize()`。已有原生 resize 回调只需宽度时允许读取 `window.innerWidth`，但必须保持原断点与滚动条口径。
- 滚动持久化必须只针对确需恢复位置的页面，按恢复语义节流或在明确时机保存，并处理最后一次位置；禁止全站每次 scroll 同步写 localStorage。nextTick 不能减少同步 I/O 或调用次数。
- 必须检查路由切换、卸载、缓存激活、断点与恢复状态，禁止通过丢失原有行为取得性能数字。临时测量脚本与产物必须放临时目录，不随业务发布。

## 正向形态与反例

```ts
// 已有原生 resize listener 的回调；断点必须来自实际项目。
const resizeBody = () => { mobile.value = window.innerWidth - 1 < 992 }
```

反例：在 resizeBody 内每次创建 `useWindowSize()`；用 nextTick 包裹每次 scroll 的 localStorage 写入就宣称异步优化完成。

## 完成标准

必须运行变更文件 ESLint 与生产 build；typecheck 的既有与新增错误必须分开报告。必须用实际回调计数检查监听不重复、普通页面不写滚动存储；这些计数不能替代浏览器性能测量。必须检查登录、菜单/标签页、表格弹层、移动断点、内存/监听增长和实际 LCP/INP 或主线程数据；未测量项必须写明。发布需独立授权与回退制品，必须保留仍被旧页使用的哈希资源并验证 HTML、压缩/缓存头、资源内容及缺失资源状态。
