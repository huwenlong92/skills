# 知识写入

适用范围：将聊天、研究、分享或操作经验整理为长期知识，或更新主题与索引。

## 分类与结构

- 必须读取仓库主题注册表、元数据和生命周期规则；只允许在已声明的知识目录与附件目录写入，禁止写入门户生成目录或工具配置目录。
- 必须先查重；重复来源须合并，观点冲突须并列记录证据与日期，禁止静默替换已确认决策。
- 必须使用稳定 ID、简短标题和明确主题；元数据字段与状态服从仓库规则，禁止根据模型自信把草稿升级为已确认。
- 正文必须先给结论与适用条件，再列步骤、限制和未解决项；聊天记录必须提炼，只有用户明确要求完整存档时允许逐轮保留。
- 必须区分用户原意、外部模型建议、可核验事实和当前 Agent 推断；动态技术事实必须查询官方或一手资料，无法核验时明确标为待确认。
- 来源必须记录原始 URL 或仓库相对路径、取得日期和已读范围；只取得部分正文或未读附件时必须保留缺失说明并使用草稿状态。
- 必须移除真实凭据、Token、私钥、密码和带认证连接串。需要保留操作形态时用无效占位符，禁止将原始 JSON 默认为长期附件。
- Markdown 链接必须指向真实目标。缺失或歧义目标必须登记待处理，禁止猜造文章与来源。

- 用户说“归档一下”表示将材料持久保存，禁止因此自动设置 archived；只有文章停用或被替代且符合仓库生命周期规则时才允许使用该状态。
- 聊天中的方法、排障、决策与摘录按[聊天入库](capture.md)选择内容结构；旧知识的版本核验、合并与链接修复按[知识维护](maintenance.md)处理。

## Source Visibility

新增、修改、移动、删除或重分类前，必须读取 [Source Visibility V1](visibility.md)，核对分类/目录/文章声明、唯一物理父链与所有受影响后代。下方及聊天入库模板中的 status 仅为生命周期；禁止按 draft/confirmed 自动填写 visibility，也不得擅自批量改变既有文章的声明。

## 正向形态

下列形态必须按仓库元数据约定调整：

```md
---
id: connection-troubleshooting
title: 数据库连接排查
topic: databases
status: draft
updated: 2026-10-15
---

# 数据库连接排查

结论：先确认实际运行环境，再检查连接参数。

## 适用条件
## 已验证步骤
## 来源与已读范围
## 待确认事项
```

反例：删除分享来源，将模型建议写成已验证结论；只有网页摘要却将笔记标记为完整。

## 完成标准

必须核对正文、元数据、来源、链接和主题索引；人工检查结论是否超出已读材料、是否遗漏不同角色与附件。提交成功前禁止宣称已经保存。
