# 仓库协作

适用范围：首次绑定、跨会话恢复、GitHub 读写和提交。所有路径以目标知识库根目录为基准。

## 目标与权限

- 必须按 [Workspace 配置](workspace.md) 确定唯一目标，再按 [Repository Resolver](resolver.md) 选择本地 Git 或远端 Provider。旧版 `WIKIOPS_REPOSITORY` 和单仓库配置不得覆盖显式 Workspace 配置；迁移前需人工确认目标，禁止隐式合并。
- 必须核对仓库私有性、默认分支和当前提交，再读取 AGENTS.md、主题注册表及命中规范。共享 Skill 仅允许专用 WikiOps 的公开默认仓库定位，禁止记录用户本机路径、私密仓库绑定或授权邮箱。
- 正文仅允许写入仓库规范指定的知识目录；门户生成目录、工具安装目录与无关仓库禁止作为长期正文存储。
- 已连接的 GitHub 工具支持写入时必须使用实际工具能力；仅有只读连接器不能通过提示词变为可写。允许使用经授权 CLI 的临时检出，不要求用户维护本地副本。

## 本地同步

- 允许保留用户指定的本地工作副本。同步前必须检查工作区和远端分支；只有工作区干净且可快进时允许 pull --ff-only。存在本地修改或分叉时必须保护内容并比较差异，禁止用 reset --hard 或强推实现同步。
- 本地改动必须验证并按已授权范围提交、推送；云端改动必须拉取后再基于最新版本继续修改，禁止维护第二套手工同步的正文。

## 修改与提交

- 必须先搜索标题、正文、来源 URL 与稳定 ID；同主题可合并时更新原文，仅在独立主题或原文职责不同时新建。
- 修改前必须读取目标文件当前版本与 SHA。API 更新必须带版本条件；多文件提交必须基于已读取的树构造且保留无关文件。
- 提交前必须重新核对远端 head。并发前进时必须重新比较、合并和验证，禁止强推或覆盖未知变更。
- 提交、PR、合并与发布必须服从目标仓库规则和用户授权；仅暂存任务文件，禁止全量暂存未知改动。
- 无写权限、规则冲突或版本无法核实时停止受影响写入，交付草稿及缺少的具体能力；禁止宣称已经落库。

正向形态：读取主题入口和既有文章 → 更新文章与索引 → 校验 → 基于最新 head 原子提交。反例：只搜索到标题就覆盖正文，或将提交成功说成已经上线。

## 完成标准

写入任务必须交付实际仓库路径、提交或 PR 链接及验证结果；人工核对未覆盖其他会话内容。写入失败时必须说明哪些内容尚未保存。只读查询不创建提交，按[知识检索与回答](answer.md)交付已读来源与证据范围。
