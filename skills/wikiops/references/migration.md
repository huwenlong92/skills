# 旧知识迁移

适用范围：导入 Obsidian、文件目录或其他系统的既有知识。必须另读知识写入规则。

## 顺序与边界

1. 必须只读盘点源文件、附件、原始路径、内容摘要哈希、Git 状态和链接；禁止修改源库、其远端或未提交改动。
2. 必须先建立目标知识规范、主题注册表和迁移清单，再按批次清洗；禁止把工具配置、缓存、聊天缓存与源 AGENTS.md 直接当知识正文发布。
3. 必须按内容识别知识、项目上下文、灵感、归档与模板；产品权威库已有文档时登记关联，禁止将旧项目讨论自动升格为当前 PRD。
4. 必须保留来源日期、旧路径与状态，记录目标路径、转换动作、重复关系、脱敏和未解决链接。未审阅材料必须标为草稿，禁止仅加元数据就声称完成语义清洗。
5. 必须先生成全量路径映射，再转换 wikilink、相对链接、标题锚点和附件；重名目标必须按源目录定位，仍有歧义时登记，禁止随机选择。
6. 凭据必须在任何远端上传前清除；扫描命中必须人工复核，原始敏感值禁止写入迁移清单和日志。附件必须单独审阅，未审阅附件禁止发布。
7. 每批必须核对源数量与目标/排除数量、可追溯哈希、链接、元数据和构建；源文件发生变化时重新生成受影响批次。

迁移清单只允许放在目标仓库声明的迁移审计目录，知识正文只允许在知识目录；禁止把临时原始导出写入共享 skill 或公开工件。

正向形态：`旧路径 → 新 ID/路径 → draft → 链接转换与待审阅事项`。反例：复制目录后删除旧库，或将全部旧笔记标成已验证。

## 完成标准

清单覆盖所有纳入盘点的源文件，排除项有理由；源库保持不变，脱敏完成，链接与构建通过。人工检查主题、重复、历史决策和来源范围；未完成的语义审阅必须单独报告。
