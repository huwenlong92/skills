# 门户与发布

适用范围：VitePress 工程、构建脚本、CI、Cloudflare 与访问控制。必须读取目标仓库门户与发布规范。

## 构建

- 必须先查看项目已有构建、校验与部署脚本；有参考实现时必须核对其输入输出与依赖后复用，禁止盲目复制业务专属模型。
- 知识正文是唯一事实源，门户内容必须自动生成；生成文件只允许在工程声明的输出目录，禁止手工维护第二份正文。
- 主题导航与搜索必须来自真实知识目录和注册表；版本信息必须来自真实提交，禁止伪造历史快照。
- 必须锁定依赖并运行工程构建与输出校验；构建中不得输出秘密，禁止上传包含私密正文的公开 CI 工件。

## 可见性与发布

- 必须确认仓库可见性、用户选择的站点可见性与发布范围、Cloudflare 目标和当前 DNS；已有明确选择时直接执行，禁止反复确认或用 skill 默认值覆盖用户指示。禁止覆盖无关应用、账户级策略或其他站点。
- 用户明确要求公开全部或部分内容时，允许直接发布对应内容；Access 可由用户后续添加，禁止因此强制索取 Access 管理权限。GitHub 私有仓库与公开只读门户允许同时存在。
- 用户要求私有门户时，必须验证自定义域名、默认域名、预览地址、正文与静态资源均不能匿名取得内容；只保护首页或自定义域名不足以通过私有验收。
- 仅在用户要求私有且保护尚未完成时，只允许部署无知识内容的测试壳；用户已明确授权公开发布时不适用此限制。
- 配置私有访问时 Allow 必须限定用户明确授权的主体，禁止 Everyone 或宽泛 Bypass。构建发布 Token 只授予发布所需权限；DNS 与 Access 可由用户在控制台配置，禁止把它们强制加入发布 Token。凭据只能使用现有授权环境与平台秘密存储，禁止写入 Git。
- 生产部署必须核对最新默认分支 SHA，过期构建必须跳过；部署失败必须保留已验证版本，禁止声称提交就是上线。
- 发布后必须对照线上 build-info 提交信息，公开站点必须验证匿名可读；私有站点必须验证匿名拒绝与授权可读。授权身份测试需要用户交互时必须明确尚未验证。

## 完成标准

必须分别报告构建、CI、部署 SHA、域名和访问验收；人工核对发布范围、匿名入口及附件/搜索资源。只有用户要求私有且缺少 Access 能力时才停止私有发布；公开发布不得被无关的 Access 门禁阻断。
