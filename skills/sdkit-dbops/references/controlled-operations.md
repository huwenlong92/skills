# Controlled Database Operations V1

适用范围：AI 请求执行已授权的数据库查询、DDL/DML、初始化和恢复时，必须读取本文。本阶段仅定义 Skill 工作流，禁止实际连接或执行。

1. 必须先确定目标环境、实例、数据库、Schema、对象、操作和执行身份；无法证明目标身份时停止，不得试连未知或疑似正式库。
2. 必须先调用 DBOPS-05 离线 Plan、History、Snapshot、Data Safety 和 Backup Decision，检查 SQL、依赖、行数上限、锁风险、兼容性和 RPO/RTO。
3. 只读结构比较必须优先使用 Schema/History 元数据；不得为了比较结构下载全量业务数据。
4. 必须按目标和风险选择现有 PITR、快照、表级或全库备份，并有独立恢复验证证据；schema-only 不能作为业务数据恢复证明。
5. 必须要求用户精确授权本次目标、操作、对象、SQL/Plan Hash 和停止条件；AI 不能自己签发、扩大或重放授权。
6. 执行前必须再次检查目标身份、Plan/History/Snapshot 是否失效、恢复保障、并发写入和权限。缺少任何可信证据必须停止。
7. 未来实际执行只能使用目标项目已确认的数据库工具（可选 sdenv、项目 Migration 或其他已核验工具），并严格遵守其现有生产禁止规则；本 Skill 不能覆盖其他 Skill 的更严格门禁。
8. 对 DROP、TRUNCATE、无条件 DELETE、批量更新、Seed/ORM 清理和受保护对象必须单独列出影响范围并请求高危专项确认；不允许以普通开发授权代替。
9. 执行必须逐步记录 SQL Hash、目标、前后状态、影响行数、执行者、时间、异常和恢复证据；出现未知提交、超出范围、锁丢失或审计失败立即停止后续步骤。
10. 失败后必须重新采集状态，不自动 down、重复执行或恢复；恢复本身需要独立授权。

完成标准：可逐项核验目标、计划、备份、授权、执行边界、验证和恢复证据；未满足时明确阻断，且不得声称实际执行完成。
