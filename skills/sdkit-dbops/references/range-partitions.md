# RANGE 分区维护与安全恢复 V1

适用范围：评审 PostgreSQL RANGE 月分区的预建、漏跑补偿、DEFAULT检查、受控数据迁移、历史清理和失败恢复时必须读取。本文负责离线计划与证据审查；本Skill V1工具不连接数据库、不执行SQL、不生成执行授权。实际操作只能交给项目已核验且已获精确授权的维护入口。正式库禁止AI直接或间接操作。

## 对象与事实核验

- 必须记录开发环境身份、实例、数据库、Schema、父表/分区OID、分区键类型、实际边界、DEFAULT挂载、约束/索引、标量引用及writer范围；环境不明时禁止试连。
- 必须使用已有项目工具提供的catalog快照，核对 `pg_partitioned_table`、`pg_inherits`/`pg_partition_tree` 和 `pg_get_expr`；禁止按表名后缀推断年龄或把同名普通表当作正确分区。
- 月区间必须为UTC月初到下月月初的半开区间；必须先转换UTC再取年月。主键/唯一约束必须包含分区键。外键、触发器、生成列、分区层级或外部依赖未知时必须停止自动方案。
- 缺失检测必须结合预期月份窗口、任务运行记录和DEFAULT按月行数；定时任务失败不等于缺少Ensure方法。不得通过无关全量迁移或重建整个Schema补偿。

## 自动预建与漏跑

- 自动维护只能对代码白名单内的有限窗口做幂等检查/空月补建。必须使用可重复周期重试，不得要求每月某一天唯一成功；窗口之外的历史缺口必须报告并转入显式计划。
- 需要补建时必须在有效事务中锁定父表及可能直接写入的相关子表，再复核挂载/边界与DEFAULT目标范围。锁必须覆盖检查到DDL完成之间的写入竞争；只检查后无锁创建属于禁止形态。
- DEFAULT已有目标月份行时必须停止该范围的普通Ensure，返回可定位父表和月份的冲突信息。不得以 `CREATE TABLE IF NOT EXISTS`、删DEFAULT、改分区约束或静默搬数据掩盖问题。
- 多个独立月份必须分别记录结果，一个历史冲突不得阻止所有未来空月检查。存在共同原子性要求的关联表必须按确定顺序锁定并整体提交。
- 不得将“重复周期补偿”描述为停机回放或启动立即补跑；项目没有对应机制时必须明确下一次调度才会执行。

## DEFAULT受控迁移

- 必须单独批准开发数据库、精确父表/月份、SQL/Plan Hash、总行数预算、批次上限、锁窗口、暂停的writer及停止条件；普通预建授权不覆盖迁移。Dry-run和 `apply=true` 不是授权或备份证据。
- 变更前必须按[备份与恢复](backup-and-recovery.md)证明覆盖范围和恢复可用性；新建一次性空库必须记录无既有数据。结构备份不能代替已有业务数据的恢复保障。
- 必须使用白名单正式维护入口；跨表编排放项目运维/迁移目录，单表Ensure保留在项目既有模型或迁移边界。禁止放进HTTP handler、普通启动、seed、每次全量迁移，或在本Skill内新增SQL执行器。
- 默认不得自动搬迁。必须先评估暂停writer，再使用数据库锁作为最终并发保护；父表写入与直接DEFAULT写入都必须被覆盖。拿不到锁、预算不足或依赖不明必须回滚并停止，禁止自动放宽超时、扩大月份或跳过错误。
- 有界月迁移允许分批DML，但所有批次必须处于同一个明确事务内：目标行暂存、从DEFAULT移出、创建/挂载精确月分区、通过父表恢复数据、校验后提交。不得将逐批提交伪称整月原子回滚。
- 超出单事务预算时，必须另定可恢复的持久暂存/停写方案和独立验收；V1不默认支持在线跨事务搬迁，不得借拆批逃避锁或备份门禁。
- 必须保持ID、分区键、载荷、追踪标识和引用不变；恢复必须显式保留原标识，禁止重新生成或误消费序列默认值。必须核对暂存/删除/恢复数、父表总行数、整行内容、非目标月份数据、DEFAULT目标月归零和 `tableoid` 路由。
- 标量引用和跨月关联必须在执行前核对，提交前再次核对；临时挪行期间不得向其他writer暴露中间状态。发现既有孤儿或跨对象引用不明时必须另立问题，不得顺便修复。

正向形态（脱敏计划，必须由已有项目工具实施）：

```text
目标: telemetry.event_log，UTC月份2026-09；DEFAULT挂载已核验
授权: 仅开发库中的该父表/月份，最多5000行，批次500行
事务: 锁父表及DEFAULT → 原子批次暂存 → 建月分区 → 父表恢复
校验: ID/整行相同、总行数相同、DEFAULT该月0行、tableoid正确
失败: 整次ROLLBACK，采集状态；未知COMMIT先调查，禁止重放
```

反例：DEFAULT已有目标月数据，直接建分区失败后删DEFAULT重试；或先提交删除，再在下一事务建分区。两者都禁止。

## 历史清理

- 清理必须是独立操作，默认Dry-run，不得因预建或迁移成功推导删除授权。必须按真实有限边界判断完整过期月份，保留DEFAULT、无限边界和未审核的嵌套分区。
- 必须审计未完成、仍可重试任务、计划执行、跨月存活引用和外部依赖。无法证明单表可独立删除时必须跳过整个关联组，不得改业务状态绕过保护。
- 必须固定对象白名单、UTC保留期、依赖顺序、锁超时及失败事务边界；先日志/子记录再父索引，使用RESTRICT，禁止CASCADE。禁止无边界删除、清空Schema或处理其他项目资源。
- DROP后的恢复依赖已验证备份；不能把重复执行幂等、事务回滚或创建空表视为数据可恢复。DEFAULT积压须先调查路由缺口，不得将其整体删除。

## 中断与安全恢复

- `rolled_back`：必须通过新快照复核分区/catalog、数据内容/数量和引用；不得只根据最后一条错误声称无变化。
- `committed`：保留执行证据，不自动DROP已建分区或反向搬迁；后续调整必须新计划、新授权。
- `unknown`（连接断开、COMMIT响应丢失、超时状态不明）：必须先调查catalog、DEFAULT月份分布、行标识/内容/引用及执行审计。确认状态前禁止自动重跑、down、删除暂存或恢复旧dump。
- 需要备份恢复时，必须独立批准恢复到新的隔离数据库并验证，再制定精确增量恢复；禁止整库回灌覆盖原库或以存在备份为由解除保护Schema门禁。
- 证据必须记录SQL/Plan Hash、对象身份、月份、预算、前后快照、影响行数、锁/超时、提交状态、执行者和恢复步骤；敏感凭据与原始业务数据不得写入共享Skill。

## 完成标准

离线计划必须明确自动空月预建、人工DEFAULT迁移/清理/恢复的边界，以及拒绝条件。项目真实隔离PostgreSQL证据至少覆盖：预建、漏月份写入DEFAULT、冲突拒绝、批次迁移、幂等、整行/引用/路由、失败事务回滚、父表及DEFAULT直接写入并发保护、保留期和跨月清理保护。缺少真实证据时标记待验证，不得把静态校验描述为数据库验收。Skill源码修改须校验分流、相对链接和既有V1不执行边界；不得自动安装或发布。
