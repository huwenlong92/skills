# 数据库安全门禁 V1

适用于数据库连接、Schema 检查、迁移计划与任何 SQL 执行建议。

- V1 工具仅允许读取项目本地配置与 SQL 文件；不得连接数据库、执行 DDL/DML、写入 History、备份或恢复。
- 未来环境检查必须先验证目标身份与环境类别；未知环境禁止试连。正式库禁止 AI 直接或间接操作，包括只读连接和通过 CI 代执行。
- 本地隔离库、远端共享开发库、预发布库的写入授权必须分开；授权绑定环境、对象范围、Plan Hash 与操作。
- `system` 和 `system_data` 默认禁止修改，只有精确对象与明确授权才允许进入受控开发库执行评估；不得推断生产授权。
- 任何破坏性 DDL、未知 SQL、DDL 隐式提交、缺少可恢复备份、History 冲突均不得自动执行。
- 不得把 `down` 当成自动回滚。执行失败必须停止、保存证据、重新采集 Schema 并重新批准恢复计划。
- 现有 Go Migration 需独立核验 `app.mode=dev` 门禁；不得以 dbops 工具绕过。

完成标准：只读行为可测试；生产库、未知环境和未授权写入始终阻断。
