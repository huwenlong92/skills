# 本地联调

适用范围：调试 Web UI、后端、SSE、process、agent-node、安装或部署验收。能力归属以[core](core.md)为准，验证范围以[testing](testing.md)为准。

## 服务与配置

- 开发时必须分开启动前端 dev server 与后端。项目有 Makefile 或等价任务入口时必须使用该入口；仅当项目没有对应任务时，才允许按项目文档使用底层命令，禁止维护另一套日常启动流程。
- 必须使用项目声明的固定端口；仅当前端采用 Vite 且项目未声明端口时使用 5173。端口占用时必须核对是否为本项目既有服务，复用或报告冲突，禁止反复换端口掩盖问题。
- 浏览器与前端/API/实时连接必须统一使用 localhost；禁止混用 127.0.0.1 造成 Cookie、CORS 或认证差异。Vite 项目必须通过已有 proxy 将 /api 转发到后端固定端口，其他工具链必须使用项目等价开发代理。
- 必须按当前开发配置启动，保持数据库、日志和资源目录的布局一致；允许读写的位置必须来自项目开发配置，禁止为联调接入生产数据、覆盖线上安装或默认复用未知数据库。
- 前端普通改动必须通过 dev server 热更新验证；只有验收 release 包、嵌入资源、安装脚本或升级流程时，才执行前端构建与对应 release 验证。禁止只为看 Vue/CSS 效果执行 cargo build --release 或重启 release 二进制。

## process、SSE 与 reporter

- 业务 runner 必须通过 sdcore 执行命令与分发事件，禁止在联调脚本中重建执行器或另起一套 SSE 基础设施。
- 涉及命令、进度或事件链路时，必须验证匹配的成功、失败、超时/取消和连接关闭行为；只要求当前改动影响的分支，禁止为局部 UI 修改启动无关长任务。
- 临时日志、测试制品和数据库只允许写入隔离开发位置，禁止污染共享数据或将凭据写入日志。任务停止后必须清理本次创建的临时资源，禁止终止不属于本任务的进程。

## agent-node

- 仅当目标项目声明有 agent 节点能力且本次任务涉及它时，才执行本节；无 agent 的项目禁止套用节点要求。
- 必须同时启动主程序与完成当前验收所需的 agent。涉及多节点行为时至少使用两个本地 agent，验证批次/节点记录、进度 SSE、失败收敛，以及本次涉及的回滚/重试。
- 必须使用稳定的本地测试节点标识与既有受控配置注入的测试凭据，禁止反复新建节点导致记录不可比较；禁止将真实 key/token 硬编码进 skill、源码或示例。
- 涉及重连、心跳、离线或任务兜底时，必须重启本地主程序并观察自动重连、节点状态和最近心跳；该步骤不授权重启线上服务。

以下是项目明确提供这些目标后的正向联调形态；目标名必须以实际 Makefile 为准：

```bash
make dev-backend
# 在独立终端启动前端。
make dev-web
# 浏览器使用项目固定端口的 localhost 地址。
```

反例：页面样式每改一次就构建 release，或启动同名远端 agent 代替本地多节点验证。

## 完成标准

- 启动入口、固定端口、localhost 主机名与开发配置一致，未误用线上数据或服务。
- 前端改动经 dev server 验证；release 只在对应验收范围内构建。
- SSE/process/agent 改动具备本地真实链路证据；无 agent 场景已明确不适用，而非伪造节点验证。
- 人工检查进度、失败收敛、重连/心跳与资源清理；未运行的链路必须明确未验证。
