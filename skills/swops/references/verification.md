# 集成与运行验证

适用范围：服务单元、权限、网络、日志、健康检查和故障排查文档，以及安装、升级、回滚或卸载后的验收章节。

## 服务与系统集成

- 守护服务必须明确低权限运行用户、配置/数据/日志权限、启动入口、依赖、启动策略与日志轮转。软件不支持独立低权限用户时，必须记录官方限制及必要权限，禁止无依据改为 root。
- 服务单元和启动项只允许位于目标发行版或部署方案声明的管理位置；配置、数据、证书必须分别放在已声明位置，禁止把运行数据写入单元目录或源码 checkout。具体路径必须从当前官方资料和已有安装解析，禁止写死个人目录。
- systemd、OpenRC 或其他 init system 的步骤必须与目标匹配；容器托管进程必须按实际编排方式验收，禁止给无 init 的镜像套用宿主机 systemctl 步骤。
- 守护服务文档必须包含开机启动配置与验证；容器必须说明对应编排的自动启动/重启策略。用户明确要求按需启动时必须记录该选择，禁止仍将开机启动标为已启用。
- 必须说明防火墙、云安全组、SELinux、AppArmor、证书与 socket/高权限组的影响。数据库、缓存和管理入口必须限制到必要访问范围；只有明确的公网访问要求及已核对的认证、加密和网络控制齐备时才允许公网暴露。
- 获得高权限 socket/组访问的风险必须在对应步骤说明，禁止只写“加组修权限”。禁止为排障永久关闭权限控制或网络安全机制。

## 验收层次

| 层次 | 必须给出的证据 |
|---|---|
| 制品 | 实际客户端/服务端版本、来源及要求的架构/编译参数/模块 |
| 配置 | 官方配置校验或内置自检；不存在时说明替代检查及局限 |
| 进程 | 对应管理器/编排中的运行状态、启动策略和真实目标实例 |
| 功能 | 匹配软件角色的最小本机请求、查询、连接或测试构建 |
| 日志 | 本次启动/操作相关错误日志与服务日志，无未解释异常 |
| 持久化与边界 | 数据位置/权限、监听范围和必要依赖符合部署方案 |

- CLI 等非守护程序不适用启动项检查时必须明确标记，禁止为凑检查项创建无意义服务。
- 功能检查必须针对已确认目标；只有当前任务已授权相应写入且隔离测试对象明确时，才允许写入型验证。禁止向真实业务库、消息流或缓存写入测试内容来证明连通。
- 只执行 --version、只检查端口或命令返回成功不能证明完整安装成功；必须按表中适用层次组合验收。
- 安装验证、升级/回滚后的验收必须对照预期版本与数据范围；卸载验证范围以[生命周期](lifecycle.md)为准，禁止卸载后继续要求服务运行。

## 排查与日常运维

- 必须提供状态、日志、配置校验、安全重载与重启入口，并写明哪些动作改变服务状态和所需授权，禁止把重启列为无影响的检查。
- 故障条目必须包含可观察症状、定位命令、原因判据、修复条件和复验；禁止堆积一次性日志或把相同命令循环重试当作排障。
- 网络/服务检查必须给出明确超时，超时后停止该检查并记录失败；禁止无限等待或通过更换未知主机寻找可用环境。
- 日志和错误说明必须脱敏，禁止输出秘密、完整连接串或无关业务数据。

正向形态：核对服务端版本与运行实例，通过配置自检、最小无写入请求及对应时间段日志确认功能；记录每项预期、实际结果和未验证部分。

反例：安装命令退出成功或端口打开，就宣布版本、认证和业务功能全部正常。

## 完成标准

- 文档具备目标 init/编排方式下的启动、日志和权限说明，允许位置与禁止位置明确。
- 各适用验收层次都有命令/观察对象、预期结果与失败处理；不适用项有原因。
- 人工检查最小功能覆盖、目标实例、网络边界、写入授权和日志脱敏。
- 未执行时只标明待验证；执行失败时必须报告具体失败层次，禁止声称安装或恢复成功。
