# 升级、回滚与卸载

适用范围：编写或评审已有安装的升级、降级、迁移、回滚和移除流程；切换安装方式必须同时读取[安装方式](installation.md)。所有操作后的验收使用[集成与验证](verification.md)。

## 现状与备份

- 必须记录当前版本、来源、安装方式、编译参数/模块、服务管理入口、运行用户及配置/数据/证书位置；禁止假设与新装示例一致。
- 必须核对目标版本支持矩阵、发布说明、迁移路径、配置格式、插件/ABI、数据格式和集群协议兼容性，明确是否要求分阶段升级与停机。
- 必须备份配置、数据、证书、旧制品与必要安装清单，并记录恢复命令、恢复目标、权限和一致性条件。备份只允许存放在用户确认的受控位置，禁止公开目录、源码仓库或覆盖唯一备份。
- 在执行有数据风险的变更前必须验证备份可恢复；文档未实测时必须把恢复演练列为执行前置条件，禁止以“已经复制目录”代替可恢复性证明。
- 缺少备份、恢复验证或兼容性依据时必须停止真实变更，文档必须明确未满足项；禁止继续推进不可逆步骤。

## 升级与迁移

- 升级必须独立列出检查、备份、停写/停止服务条件、替换软件、配置/数据迁移、启动和验收，禁止把全新安装步骤原样作为升级流程。
- 软件支持在线重载时必须说明重载能生效的内容及验证方式；需要加载新二进制或不支持热更新的参数时必须重启，禁止把配置重载当作版本更新。
- 跨安装方式或主机迁移必须明确新旧位置、文件所有权、数据一致性、服务切换与退回点；禁止让两套服务同时争用同一数据目录、端口或服务单元。
- 必须定义逐阶段停止条件，包括校验失败、配置不兼容、迁移错误、健康检查失败与数据异常。任一条件触发必须停止后续步骤，保留日志与现场，禁止自动删除旧制品或备份。

## 降级与回滚

- 必须区分软件降级与完整回滚。只有官方明确支持当前数据/配置格式被旧版本读取，且匹配环境验证通过时，才允许仅切回旧二进制或镜像。
- 涉及不可逆数据迁移时，必须给出恢复匹配备份及处理切换后新增数据的方案；无可接受恢复路径时必须标记不支持直接回滚，禁止承诺降级即可恢复。
- 回滚必须写出触发条件、停写范围、旧制品/配置、恢复顺序、失败处理与验收。禁止覆盖唯一恢复点或把回滚命令混入正常升级。

## 卸载与清理

- 卸载必须按安装所有权执行：软件包走包管理器，源码/二进制按安装清单移除，容器仅移除已确认的实例与相关定义。禁止猜测文件列表或批量清理无关镜像、卷、包与用户。
- 普通卸载必须保留数据、配置、证书与备份，并写清保留位置。彻底删除必须单独成节，列精确对象、依赖、备份/恢复要求及不可逆影响，仅在用户明确要求这些对象时允许执行。
- 删除系统用户或组前必须核对文件所有权与其他服务依赖；禁止因软件已卸载而直接删除共享账户。
- 卸载后必须核对目标进程、监听端口、服务单元/启动项和软件文件已按范围移除，保留数据与其他服务未受影响。

以下是脱敏流程形态，目标和命令必须由本次真实软件资料补齐：

```text
现状清单 → 一致性备份 → 隔离恢复验证 → 兼容性确认
→ 按阶段升级/迁移 → 配置与服务验收 → 最小功能验收
失败：停止写入 → 按已验证方案恢复 → 重新验收并记录未恢复的数据范围
```

反例：升级后程序起不来就直接替换旧二进制，忽略已经迁移的数据格式；或在卸载步骤中顺手删除持久卷。

## 完成标准

- 升级、迁移、降级、回滚、普通卸载与彻底清理边界明确；不适用项必须说明原因。
- 每个有风险阶段都有前置条件、停止信号、恢复路径与验证动作；不可回滚部分没有被隐藏。
- 人工检查备份一致性与恢复证据、停写边界、新增数据处理、精确删除对象及共享依赖。
- 文档必须区分已演练与待执行；真实操作失败必须报告软件、数据和恢复状态，禁止仅报告命令退出码。
