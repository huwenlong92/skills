# 文档组织与交付

适用范围：新建、更新或评审 swops 文档。本文定义文档结构和核验状态，具体安装、生命周期和服务规则分别由对应 reference 维护。

## 目的地与范围

- 写入前必须搜索目标文档库的同主题内容。已有文档覆盖相同软件、平台与操作场景时必须更新原文；仅当平台、edition 或操作主题需要独立维护时允许新建，并建立关联，禁止重复创建同一流程。
- 文档必须写在用户指定文档库或目标项目声明的文档位置，遵守其 AGENTS.md；禁止为了交付安装说明修改共享 skill 的规则或把笔记放进业务源码目录。目的地未确定时必须先在对话交付草稿，禁止猜测写入路径。
- 仅修改命中内容并核对关联章节。完整安装文档必须覆盖下面全部章节；局部说明只要求命中章节，但必须链接现有基础说明或写清必要上下文。

## 完整文档结构

```md
# Linux 安装软件名

结论、推荐方式及其理由，不适用范围。

## 支持范围与版本
## 安装方式选择
## 安装前检查与备份
## 安装步骤
## 配置、权限与系统集成
## 验证
## 升级、迁移与回滚
## 卸载与数据保留
## 日常运维与常见问题
## 官方来源与核验日期
```

- 软件名、edition、release channel、发行版/版本、架构、init system 和 root/sudo 权限必须明确；适用范围较大时必须提供官方支持矩阵，并明确实际写出了哪些平台的命令。
- 所有安装方式的取舍必须按[安装方式](installation.md)给出；被要求的源码章节允许拆为同专题独立文档，但主文档必须链接过去，禁止只写“自行编译”。
- 源码、离线安装或复杂集群主题需要独立命令和验收时允许拆分；主文档必须保留选择条件、入口与相关链接，禁止创建无人引用的孤立笔记。

## 命令与来源

- 命令必须按实际目标平台分组，明确在哪台已确认主机/容器、什么用户和工作目录执行，给出前置条件、停止条件与预期结果。禁止把不同发行版命令串成一键脚本。
- 包名、版本、URL、指纹与路径必须来自本次核验的官方资料；未知值必须写为明确占位符并说明替换来源，禁止交付看似可直接执行的虚构安装地址。
- 凭据必须采用目标环境既有的安全注入方式；禁止在示例、截图、日志、frontmatter 或正文填写真实密码/Token。
- 破坏性步骤必须单独标注目标、影响与恢复条件；禁止将 rm -rf、删除卷、清空数据或强制覆盖混入普通安装。
- 每项时效事实必须有直接支持它的官方来源与核验日期。仅核验文档时不能写“实测成功”；执行结果必须另列真实环境、检查对象和结果。

长期维护的安装笔记必须记录以下元数据；目标文档系统不支持 YAML 时，必须在正文提供同等字段。示例日期是占位值，禁止把当前日期自动当作已核验日期：

```yaml
---
tags: [软件名, Linux, 安装, 运维]
status: evergreen
created: YYYY-MM-DD
updated: YYYY-MM-DD
verified: YYYY-MM-DD
source:
  - 官方安装页
  - 官方发布与安全公告页
---
```

verified 仅表示相关版本、支持范围、仓库与命令已经对照官方资料核验；没有完成核验时必须省略该值并记录待核验项，禁止伪造日期。该字段不证明真实命令已经执行。

## 完成标准

- 文档的目的地、范围与已有内容关系明确，无重复流程或失联链接。
- 命中章节满足相应 reference；命令有平台、权限、位置、占位来源与失败处理。
- 人工核对官方来源直接支持对应事实、核验日期真实、秘密已脱敏，已执行与待执行状态清楚。
- 写入文档后必须检查相对链接与专题索引；新建或拆分时必须更新已有对应索引，禁止创建无关联入口的文档。
