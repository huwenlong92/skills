# 安装方式与来源

适用范围：选择安装方式、核验发行渠道与供应链，编写新装或切换安装方式的步骤。文档格式以[文档交付](documents.md)为准，运行验收以[集成与验证](verification.md)为准。

## 方式选择与安装前检查

- 必须评估发行版仓库、软件官方仓库、源码编译、官方便捷脚本、容器与静态二进制，逐项说明包含或排除理由。必须对比版本、安全更新来源、配置/数据目录、服务管理、模块兼容性及升级/回滚/卸载成本。
- 必须先选择满足版本、平台、模块和授权约束的官方软件包；仅当官方软件包不满足其中至少一项，或用户明确选择其他方式时，才采用相应源码、容器或二进制方案。发行版包与软件官方包必须区分维护方，禁止混用来源。
- 用户要求“最新版”时必须明确 stable、mainline、LTS、GA 或预发布含义，并记录核验日期；禁止只写没有定义的 latest。软件提供官方源码且用户要求最新版、自定义模块、编译参数或底层依赖时，必须包含源码编译章节或链接同专题独立源码文档。
- 必须从上游官方安装页、发布页、支持矩阵与安全公告核验事实。第三方资料只允许补充线索，禁止作为命令与信任根的唯一来源。
- 安装前必须检查发行版/代号、架构、内核、init system、CPU/内存/磁盘资源、包/进程/端口冲突、服务用户及已有配置、数据、证书、模块和编译参数。已有安装必须转入[生命周期](lifecycle.md)判断，禁止直接套用新机流程。
- 覆盖、替换或移除冲突组件前必须说明影响范围并准备可恢复备份；资料或现状不足以判断影响时必须停止相关步骤，禁止用强制参数试错。

## 软件包与 repository

- 必须使用目标发行版和软件版本支持的官方仓库格式及包管理器入口，核对候选版本来自预期 repository 后才允许安装。
- 引入签名密钥必须核对官方完整指纹、有效期与轮换说明；必须说明仓库切换与 stable/mainline/LTS 的关系，禁止同时启用互斥来源。
- 禁止通过 trusted=yes、gpgcheck=0、关闭 TLS 校验或忽略签名错误绕过供应链验证。核验失败必须停止安装，禁止把关闭校验作为排障方案。
- 包管理器管理的文件必须由对应包流程维护；禁止用手工复制二进制覆盖这些文件而继续声称由包管理器负责升级和卸载。

## 源码编译

- 必须说明为何需要源码以及官方包不能满足的条件；固定源码版本、官方获取入口、签名或可信 checksum、发行版构建依赖和关键构建参数。
- 多上游组件必须列出 daemon、CLI、运行时与插件边界。必须先使用官方产品发布清单锁定的组件组合；仅当上游没有该清单时，才按官方兼容矩阵固定组合并执行联调，禁止拼接各仓库未经验证的最新版。
- 必须写明源码/构建工作目录、安装前缀、用户、配置、数据/缓存、日志位置及权限，禁止把源码工作目录当作长期数据目录，也禁止覆盖包管理器拥有的文件。
- 必须包含编译、安装、服务单元、启动策略与日志轮转；实际参数必须保存在构建日志、清单或软件支持的参数查询输出中。不得只交付 make && make install。
- 必须维护安装文件清单与旧版本制品，说明 ABI、动态模块、系统库和安全更新责任。源码安装不自带包管理器的依赖升级与卸载保障，升级和移除必须遵守[生命周期](lifecycle.md)。

## 容器与静态二进制

- 容器安装必须核对官方镜像来源、版本、目标平台、端口、运行用户、配置挂载与持久化目录。生产数据必须保存在明确管理的持久化位置，禁止只保存在可替换容器的可写层。
- 容器镜像引用、Compose/运行参数与持久化资源必须分别说明；替换容器必须保留已确认数据与配置，禁止以删除卷作为普通升级步骤。共享镜像与 builder 的专项要求由目标项目规则决定，禁止因本 skill 擅自发布镜像。
- 静态二进制必须核对平台、架构、ABI/系统依赖与签名或可信 checksum，记录版本与安装文件清单。可执行文件只允许落在目标部署方案声明的前缀，配置、数据和日志必须分别管理，禁止将秘密或运行数据写入下载/解压临时目录。
- 官方便捷脚本必须先下载、审查，存在官方 dry-run 时必须先使用；生产环境禁止 curl ... | sh。未提供 dry-run 时必须明确记录，并在匹配的隔离环境验证，禁止虚构支持的参数。

正向形态：先明确目标平台与版本，从官方发布页核对源码/二进制和验证材料，再生成“获取 → 验证 → 安装到声明前缀 → 配置服务 → 验收”的独立步骤。

反例：下载未知来源制品，不验证就覆盖系统二进制；或用通用 Docker run 命令忽略数据卷与目标架构。

## 完成标准

- 安装方式的取舍、官方来源、版本/平台约束和核验日期齐全；命令没有混用仓库、版本或安装所有权。
- 命中的方式具备必要来源验证、文件位置、权限与维护责任；核验失败有明确停止条件。
- 与[生命周期](lifecycle.md)及[集成与验证](verification.md)引用一致；不适用的方式和检查必须注明理由。
- 人工检查编译参数、组件组合、ABI、持久化位置及所有覆盖/冲突处理步骤；未执行的命令不得标为通过。
