# 交互原型

适用范围：生成、修改、完善或继续开发产品交互原型。执行前必须读取本文件以及 [仓库与项目路由](repository.md)、[提交与验收](publishing.md)。

## 交互与视觉

- 必须交付真实可操作的 HTML 原型，包含任务要求的导航、状态切换、表单、弹层及关键交互；静态图片不能替代可操作原型。
- 必须遵守目标项目已经确认的产品规则、视觉设计和交互约定；不得擅自更改业务规则。
- 若用户明确只要求视觉概念图而非可操作原型，则只交付用户指定的媒介，不冒充 HTML。
- 已有原型必须以当前 Latest 和版本中心为基础增量迭代；不得从旧快照覆盖最新版本。

## 版本与提交

1. 从目标仓库 `AGENTS.md` 确认版本编号、历史目录、Latest 指针、项目版本中心与首页索引规则。
2. 生成新版本后必须按规则同步 Latest、项目版本中心、全站入口、项目路由状态与版本说明，并核对目标文件实际存在。微小改动是否需要独立快照以目标仓库规范为准。
3. 原型任务授权包含必要的配套 PRD、设计规范、技术文档增量更新；必须逐项检查有无实质变化，未变化则在版本说明中记录原因，不得为凑更新量重写。完成后按目标仓库规范自动提交，无需用户再次要求提交；但无权限或用户明确要求不提交时不得绕过。
4. 必须按 [提交与验收](publishing.md) 验证构建、发布和线上访问；仅 GitHub 提交成功不能称为上线。

## 允许与禁止

允许：目标仓库规范规定的原型目录、历史版本和 Latest 索引。禁止：随意另建版本目录、覆盖已归档快照、把待验收版本描述为已验收。

## 完成标准

必须报告真实版本、修改路径、Commit SHA、预览 URL、构建与线上验证状态；无法确认的步骤标为未验证。
