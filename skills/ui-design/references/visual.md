# 视觉设计

适用范围：新建或修改 UI 视觉稿、布局、配色、组件层级时读取。

- 必须先读取已有产品设计系统和用户确认的设计参考；无设计系统时根据产品定位建立可复用的视觉层级，不能把某一项目的固定色值、顶栏高度或圆角作为通用强制值。
- 必须区分页面骨架、导航、内容层级和操作优先级；同一视图中重复的导航与 Header 必须明确所有权，不能凭 CSS 隐藏宿主区域代替正式布局约定。
- 控件应具有可辨识的默认、悬停、焦点、禁用、错误等适用状态；不能只设计静态默认状态。
- 组件优先消费项目已有 Design Token；只有项目缺少相应 Token 时，才提出增量设计 Token 建议，不得未经授权修改项目组件库。
- 必须避免为填满设计稿虚构业务数据、项目数量、权限、发布时间或真实产品能力。

正向形态：先确定页面导航层级、内容区、主要操作与状态反馈，再给出颜色、排版和组件规范。反例：只给一张好看的首页图片，未说明页面状态，却声称整套 UI 已设计完成。

## 完成标准

可指出每个设计页面的主要结构、视觉基线、组件状态及其与既有设计系统的关系；未知业务内容标注为示例。
