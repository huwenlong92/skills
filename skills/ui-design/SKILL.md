# UI Design · 设计与交接

适用于用户要求设计、修改、评审 UI 设计稿，或将已有设计稿整理为可执行开发交接的任务。仅开发代码、修复前端 Bug、发布原型或维护 PRD 时不得作为 Primary。

## 分流

| 任务 | 读取 |
|---|---|
| 页面视觉、风格、布局、组件设计 | [视觉规范](references/visual.md) |
| 页面流程、弹窗、表单、状态 | [交互规范](references/interaction.md) |
| 多端设计、可访问性 | [响应式规范](references/responsive.md) |
| 交给 Codex 或其他开发 Agent | [设计交接](references/handoff.md) |
| 评审设计稿、对比实现截图 | [设计复核](references/review.md) |

## 协作边界

- 纯设计任务以 ui-design 为 Primary；涉及已有产品时 Foundry 只提供已确认的 PRD、决策和项目定位，不接管设计执行。
- PRD、项目文档同步、原型源码存放与迁移、Git/PR、发布仍归 Foundry 和目标仓库规范；正式前端实现由匹配的技术栈 Skill 负责，ui-design 只提供设计约束。
- 当前 Agent 不支持图像输出时，只能交付明确标记的文本设计方案或交接说明；不得把文字描述冒充已生成的设计图。用户明确要求图片时使用实际可用的图像工具。
- 先读取已有设计基线，不擅自替换用户确认的风格、信息架构、业务规则或真实数据来源。
- 按任务复杂度输出最小交接：局部修改只需设计稿/说明、变更范围与验收；新模块补充页面与状态；大型项目才生成完整交接包。
- 设计交付不授权修改业务源码、提交、发布、安装工具或操作数据库。

## 完成标准

明确设计稿是否实际生成、所覆盖页面和设备、关键交互状态、尚未确定的业务规则、素材来源及 Codex 可验证的验收条件。没有执行浏览器测试时不得声称已完成视觉实现验收。
