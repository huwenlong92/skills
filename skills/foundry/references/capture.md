# Foundry 知识检索与捕获

适用范围：用户没有点名 Foundry，但任务依赖既有项目需求、架构决策、设计或研发进度；或当前讨论出现值得沉淀的产品想法、决策、PRD、技术方案与项目验收。必须先按 [仓库路由](repository.md) 确定 Workspace 和项目身份。

## 自动检索

1. 问题含明确项目名、slug、产品功能或历史决策时，必须先读取目标 Workspace 的 PROJECTS.md 与项目相关索引；唯一定位后才按需读取 PRD、docs、tech、design、research 和已确认决策。
2. 仅当索引无法定位且问题确实依赖已有项目资料时，才扩展别名、相关项目和目录；slug 歧义时禁止猜测目标项目。
3. 只读查询不创建文件或 PR；实际代码状态必须与项目仓库 Git/测试核对，不把产品计划当成实现。
4. 当前会话必须复用已读索引、正文与来源版本；禁止为身份核验、补引用或每轮回答重复读取已有有效全文。仅当来源版本变化、已有内容截断或缺少影响结论的段落时，才允许补读必要范围，并说明补读原因。
5. 需要 Wiki 技术经验时仅把通用知识检索交给 WikiOps，项目文档事实源仍由 Foundry 管理。

## 候选分类

| 信号 | 结果 | 停止条件 |
| --- | --- | --- |
| 初步产品设想 | Idea 候选 | 不自动建项目 |
| 已有目标用户、问题与独立交付物 | Project Candidate | 未获启动确认不创建 slug |
| 用户明确启动且路由无冲突 | Project 初始化候选 | 未获写入授权不提交 |
| 用户确认功能、技术选型或设计取舍 | PRD/技术方案/ADR 候选 | 不将未确认建议升级为决定 |
| 实际开发完成并有测试证据 | 实现/验收文档候选 | 不把 Commit 当作部署成功 |

## 去重与交接

- 必须先查已有项目、slug、别名和相同主题文档；同项目、同主题且适用范围一致时必须增量更新，仅当主题独立或原文职责不同时才允许新建；禁止覆盖已确认决策、迁移声明或历史版本。
- 仅在阶段完成、用户确认重要决定、话题切换或交接时，且有实质候选，输出简短的“建议沉淀”摘要：目标项目、文档类型、已确认/待验证、建议更新/新建及未执行的写入。
- 当前会话候选不构成持久记忆；需要跨会话保留时只能按授权写入现有项目文档或交接记录，不另建候选数据库。
- 非原型文档只有用户明确要求同步或已有对应持续维护授权时才允许写入；正式项目初始化、原型发布和跨 Workspace 写入服从原有独立门禁。

## 完成标准

能正确区分已有项目与新项目候选、已确认决策与讨论、产品事实与代码实现、Foundry 与 WikiOps 归属；不因普通闲聊创建项目，不因自动识别产生未经授权的仓库提交。
