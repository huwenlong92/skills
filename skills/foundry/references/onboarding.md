# 项目初始化与导入

适用范围：用户要求 foundry init、foundry import、foundry sync，或在新会话中指定项目、模块及新项目名称。执行前必须读取 [Workspace 配置](workspace.md)、[仓库与项目路由](repository.md) 及目标仓库最新的项目路由协议。发布者默认仓库使用 `projects/product-docs/docs/foundry-routing-and-import.md`；其他 Workspace 必须从其 `AGENTS.md` 发现等效协议，缺失时停止写入并提示初始化，不得套用发布者路径。

## 项目路由

1. 必须读取最新 PROJECTS.md，再读取已存在项目的 profile.json 和 modules.json。模块标识必须属于当前项目。
2. 精确 slug 和已登记别名可以唯一匹配；模糊匹配仅提供候选，不得直接写入。
3. 同一会话已明确的项目和模块可以沿用；若当前输入显式指定其他目标，必须以当前输入为准。
4. slug、别名、中文或英文名称、模块 ID 发生冲突时必须停止创建和写入，说明冲突对象并询问用户选择关联现有项目、采用其确认的新 slug 或取消。
5. 禁止自动追加编号、覆盖、合并、修改已存在 slug 或历史版本。用户确认后重新读取最新仓库检查并发冲突。

## init

确认名称、slug、定位和实际客户端。先生成拟修改文件的预览；仅在明确授权提交后写入。没有真实产物时禁止创建空原型、官网地址和历史版本。若同时要求设计交互原型，遵守 [交互原型](prototypes.md) 与 [提交与验收](publishing.md)。

## import

只读扫描用户授权且工具实际可访问的本地代码、README、依赖声明和已有文档。无法访问时明确说明，禁止假称已扫描。排除环境变量值、密钥、凭据、个人信息和数据库导出；不复制完整业务源码。先出项目匹配、模块、已实现事实与文档差异预览。用户确认 slug 和写入范围后方可提交。

## sync

读取现有项目档案、PRD、设计、技术文档及已确认决策后对比来源；仅增量更新有根据的内容，不将代码推断冒充已确认决策。普通文档只有明确要求同步才提交；原型按已授权交付规则执行。

## 完成标准

必须明确项目 slug、模块 ID（适用时）、来源、冲突检查、预览或实际变更、授权状态，以及真实提交、构建、部署和线上访问状态。工具无法访问本地目录或仓库时明确报告未完成项。
