# 仓库与项目路由

适用范围：任何需要定位、读取、创建、修改或发布产品仓库内容的任务。操作前必须读取本文件。

## 专用默认配置

本 Skill 为仓库所有者专用，默认目标如下；这些是公开定位信息，不是访问凭据。

| 配置 | 值 |
|---|---|
| GitHub 仓库 | `huwenlong92/product-docs` |
| 默认分支 | `main` |
| 产品文档站 | `https://pm.sdkit.cn` |
| 交互原型站 | `https://ui.sdkit.cn` |
| 项目路由 | 仓库根目录 `PROJECTS.md` |
| 目录、版本、发布权威规范 | 仓库根目录 `AGENTS.md` |

用户未指定其他仓库时，必须直接使用以上默认目标，不得反复询问仓库地址。仅当用户明确指定另一个仓库时允许切换，并必须重新读取新仓库的权威规范。不得将项目列表、原型版本、文件目录快照固化到本 Skill。

## 定位与读取

1. 默认使用本文件的专用仓库与分支；用户明确覆盖时使用用户指定目标。禁止从模糊历史内容猜测替代仓库。
2. 必须使用已连接的 GitHub 插件读取根目录 `PROJECTS.md`、`AGENTS.md`，并读取后者引用的任务相关子规范。GitHub 插件不可用或规范无法读取时，停止仓库写入，不得冒充已授权访问。
3. 使用 `PROJECTS.md` 中的项目 slug、别名及路由识别项目。存在多个候选时必须确认，禁止根据近似名称随意创建项目。
4. 再读取目标项目已有 PRD、设计、技术、决策及版本记录。已有文件必须增量更新，禁止无理由覆盖历史。
5. 只有目标仓库 `AGENTS.md` 明确允许时才创建目录、修改版本索引或发布；不能把本 Skill 中的示例路径当作真实目录。

## 自动识别与冲突确认

- 新会话的 `@slug` 或 `@slug/module` 必须以最新 `PROJECTS.md`、`profile.json`、`modules.json` 进行唯一匹配；不能将别名相似作为创建项目的依据。
- 当 slug、别名、正式名称、已有目录或模块 ID 发生冲突时必须暂停写入，向用户说明冲突对象并询问新 slug、关联现有项目或取消；禁止自动追加编号、覆盖、合并和改动已有标识。
- 定位项目时先读取最新 `projects/product-docs/docs/foundry-routing-and-import.md`，按其中流程处理新旧会话。

## 路径边界

- 允许位置：目标仓库最新规范指定的项目目录、原型目录与索引文件。
- 禁止位置：未在规范登记的平行目录、旧迁移副本、任意工作站绝对路径。
- 如果项目目录或分支状态与规范冲突，必须先停止写入并报告差异。

## 完成标准

必须能指出默认或明确覆盖的目标仓库、分支、项目 slug、所依据的两份权威文件及实际修改路径。无法读取的内容必须标注未核实。
