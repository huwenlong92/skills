# 提交与发布验收

适用范围：所有本地 Git、Git Provider 写入、原型发布、线上预览及故障排查。发布前必须读取本文件。

## 前置条件

- 必须有明确目标仓库、分支、允许修改的路径以及相应本地 Git 或 Provider 的实际写入权限；访问能力不可用时不得宣称提交成功。
- 必须读取目标仓库最新 `AGENTS.md`，以其构建命令、发布目录和版本机制为准。
- 非原型文档只有用户明确要求同步时才提交；原型完成后依 [交互原型](prototypes.md) 自动提交。
- 破坏性覆盖、删除历史或修改已确认决策，必须取得当前任务明确授权。

## 双环境交付策略

- 本地 Codex 优先使用已验证本地工作区，尊重当前分支（通常为 main），可以按任务授权修改、测试及本地提交；远端推送前必须核对远端 HEAD、保护规则与授权。不得强推或覆盖他人修改。
- ChatGPT Web 等无本地文件访问能力的环境，默认在 Provider 上使用独立任务分支与 PR/MR。平台不支持审查请求时必须报告，禁止擅自直接推主分支。
- GitHub 以 PR、GitLab 以 MR 等实际平台机制交付；平台能力不足时不得伪造 CI 或合并状态。详见 [Resolver](resolver.md)。

## PR 优先的提交策略

- 在默认产品仓库执行写入前，读取最新 `AGENTS.md` 和 `standards/git-workflow.md`，以其实际约束为准。不能因 Skill 内的流程描述代替仓库授权。
- **默认走 PR**：交互原型及 Latest/Overview 版本变更、PM/UI 页面与交互、构建和 CI 脚本、项目/模块数据模型、仓库规范变更。
- **可直接提交**：用户明确授权同步的单项目、低风险普通文档小修改；若跨项目、结构性或大规模修改则使用 PR。用户只要求讨论或草稿时不得提交。
- 同一任务尽量汇总为一个短期分支和一个 PR；不要每修改一个文件就创建新的 PR。分支从目标仓库最新默认目标分支创建，命名采用 `feat/`、`fix/`、`docs/`、`test/` 或 `refactor/`。
- PR 创建后检查真实 CI；失败则修复，不合并。合并前确认最新 head SHA、目标分支是否变化、是否冲突及用户授权。优先 Squash Merge。用户明确要求只创建 PR 或暂不合并时必须停在 PR 阶段。
- PR 合并后返回 PR URL 和合并后的 SHA（不把分支提交 SHA 冒充最终 SHA）。部署和访问另行核验，不能将 PR 合并视为发布完成。
- 原型完成后的自动提交授权仍有效，默认通过 PR 实施；但无权限、用户明确禁止提交或要求等待时不能绕过。
- 紧急直接写入 main、强制覆盖、历史删除或回滚均须明确授权；回滚优先新建修复 PR 或 Revert，而非重写已归档历史。

## 分阶段验证

1. **提交**：取得真实 Commit SHA；失败时停止并报告。
2. **构建**：运行仓库指定的校验与构建，或读取可信 CI 结果；不能只根据提交成功推断构建成功。
3. **部署**：确认托管平台实际部署的 Commit 与目标版本一致。部署失败时不得声称已上线，必须报告失败阶段；无法访问平台时标注部署未验证。
4. **访问**：请求真实页面、关键静态资源及版本标识，核对 HTTP 响应与页面内容；仅已知域名不构成成功证据。
5. **故障**：定位构建日志、部署产物和线上响应的具体差异；禁止无依据重复改 CSS 或宣称缓存是根因。

## 结果格式

必须包含项目、文档类型或原型版本、修改路径、真实 Commit SHA、在线地址（如适用）、构建状态、部署状态、访问验证状态。缺失的证据写“未验证”，不得补造 SHA、URL 或成功结果。

## 完成标准

所有声称成功的环节必须有实际工具结果或平台证据；发布失败必须说明阻断步骤及后续核验对象。

## 多会话并行交付与自动合并

- 多个 ChatGPT 会话与本地 Codex 并行时，远端交付默认使用独立任务分支与 PR/MR；本地允许在当前分支编辑，但提交和推送前必须检查远端变化及共享文件冲突。
- 写入前重新读取目标仓库 Git 工作流规范；提交前核对目标文件版本与远端目标分支。项目索引、AGENTS.md、Latest、Overview 与 CI 配置均视为共享资源。
- 仅当用户已授权自动合并、PR/MR 非 Draft、必需 CI 真实成功、无冲突及待人工验收事项时才允许自动合并；未配置或缺失的检查不得当作通过。
- 合并前再次核验 Head SHA 与目标分支状态。出现版本漂移或冲突时保留 PR/MR 并停止，不得强推。
- 合并与部署严格分离；不能因为目标分支更新就认定获得生产部署授权。
