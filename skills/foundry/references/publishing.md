# 提交与发布验收

适用范围：所有 GitHub 写入、原型发布、线上预览及故障排查。发布前必须读取本文件。

## 前置条件

- 必须有明确目标仓库、分支、允许修改的路径以及已连接 GitHub 插件的写入权限；插件不可用时不得宣称提交成功。
- 必须读取目标仓库最新 `AGENTS.md`，以其构建命令、发布目录和版本机制为准。
- 非原型文档只有用户明确要求同步时才提交；原型完成后依 [交互原型](prototypes.md) 自动提交。
- 破坏性覆盖、删除历史或修改已确认决策，必须取得当前任务明确授权。

## 分阶段验证

1. **提交**：取得真实 Commit SHA；失败时停止并报告。
2. **构建**：运行仓库指定的校验与构建，或读取可信 CI 结果；不能只根据提交成功推断构建成功。
3. **部署**：确认托管平台实际部署的 Commit 与目标版本一致。部署失败时不得声称已上线，必须报告失败阶段；无法访问平台时标注部署未验证。
4. **访问**：请求真实页面、关键静态资源及版本标识，核对 HTTP 响应与页面内容；仅已知域名不构成成功证据。
5. **故障**：定位构建日志、部署产物和线上响应的具体差异；禁止无依据重复改 CSS 或宣称缓存是根因。

## 结果格式

必须包含项目、文档类型或原型版本、修改路径、真实 Commit SHA、在线地址（如适用）、构建状态、部署状态、访问验证状态。缺失的证据写“未验证”，不得补造 SHA、URL 或成功结果。

## 完成标准

所有声称成功的环节必须有实际工具结果或平台证据；发布失败必须说明阻断步骤及后续核验对象。
