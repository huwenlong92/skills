# 国际化与 SSR 隔离

适用范围：修改模板的语言资源、语言切换、国际化插件、表单翻译或多语言 SSR 时必须读取。路径以目标项目根目录为基准；必须先核对当前依赖和实际导出，禁止假定模板 main 已被消费。

## 职责与状态

- 语言配置、每请求实例工厂及框架公共词条必须放在 `layers/core/i18n`，项目词条必须放在 `src/i18n/locales/<locale>/<module>.json`；禁止复制中英文页面或把业务词条写入 core。
- 必须复用已有 Vue I18n 实例与 `useAppI18n`；每个 SSR 请求必须建立独立实例，禁止在模块顶层共享可变 locale 或向 Pinia 再复制一份语言状态。
- 语言偏好必须由 Cookie 保持 SSR 与客户端初始化一致；非法值必须回退已声明默认语言。切换必须更新 HTML lang、标题和 Element Plus locale，不得强制重建整页或清空表单。
- 本地化 URL 与界面翻译必须分开判断；只有确有多语言 URL 与 SEO 需求时才允许增加路由策略，不能仅因翻译界面复制路由。

## 文案与表单

- 词条必须用稳定语义 key；动态名称、数字、日期、复数必须使用插值或库提供的格式化能力，禁止拼接句子碎片或依赖中文错误文字做业务判断。
- 菜单、校验规则等翻译派生值必须使用 computed；长期错误必须保留 key 并在展示时翻译。调用方传入的文案不得被组件重新解释。
- 语言切换必须保留表单值、路由与交互状态。Element Plus 表单必须关闭规则变化自动校验，只更新已处于错误状态字段的提示，禁止在切换语言后让未触碰字段全部报错。
- 服务端原始消息及用户内容不自动翻译；需要时必须采用稳定错误码或服务端语言协商，不能伪造翻译结果。
- 自行接入 `vue-i18n` 的现有 core layer 必须核对 `build.transpile` 的实际配置；禁止用开发服务正常代替 Node SSR 产物验证。

## 正向形态与反例

```ts
const { t } = useAppI18n()
const rules = computed(() => ({ name: [{ required: true, message: t('catalog.nameRequired') }] }))
```

```vue
<el-form :model="form" :rules="rules" :validate-on-rule-change="false" />
```

反例：模块级 `createI18n` 对象供所有 SSR 请求共享，或切换语言时清空 form 并重建页面。

## 完成标准

必须验证多语言 key/插值一致、非法语言回退、并发 SSR 用户隔离、Cookie 持久化、已挂载组件与错误提示更新、表单值保持。必须检查长文案及小屏布局，并运行实际 scripts 中的 i18n 测试、typecheck、生产 build；未运行项必须说明原因。Node SSR 产物必须检查初始化异常，HTTP 200 不能单独证明成功。
