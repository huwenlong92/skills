# sdkit-ui-design

跨项目 UI 设计、图片基线归档与开发交接 Skill V1.1。负责设计稿、交互状态、响应式与设计复核，不负责正式业务代码、Git 发布或部署。

## 使用场景

- 设计桌面和移动端页面，依据已确认 PRD 生成 UI 图。
- 将 ChatGPT Web 图片交给本地 Codex 开发时，先保存可追踪的设计基线。
- 基于图片直接开发正式业务，或先做交互原型。
- 对比浏览器实现截图与已保存设计稿，修复视觉偏差。

## 自动归档

用户明确要求基于实际图片迭代或开发、且当前项目写入授权覆盖设计资料时，Codex 必须先执行 [基线归档协议](references/baseline.md)：通过 Foundry 解析权威仓库、读取真实图片字节、SHA-256 去重、保留修订、增量更新 DESIGN.md、读回校验，再进入开发。已立项归项目仓库；未立项经 Foundry 核验后可暂存产品文档仓库。已有设计目录优先，无约定才默认 docs/design/。

只读讨论不写入；图片只在 Web 对话中而本地不可访问时停止并报告 BLOCKED。归档不授权 Commit、Push、PR、合并或发布。

## 开发模式

- `production`：设计基线完成后，由技术栈 Skill 实现正式业务并验证真实 API、权限、构建及视觉。
- `prototype`：设计基线完成后，遵守 Foundry/项目原型规范完成模拟交互与浏览器验收。
- `undecided`：只保存设计与交接说明，不生成业务或原型代码。

## 入口与验收

从 [SKILL.md](SKILL.md) 选择 references。无需个人配置或独立 CLI；图片生成取决于当前 Agent 的可用工具。必须分别报告静态测试、真实图片文件测试、Codex 行为验收与浏览器视觉验收，未执行的不得标记通过。
