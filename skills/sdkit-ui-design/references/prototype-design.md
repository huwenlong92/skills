# 交互原型设计工作流

适用范围：用户要求可点击、可运行的交互原型，或需要设计原型状态与流程时读取。

- 必须先定义页面 ID、导航、用户动作、状态转换、异常恢复和权限边界。
- 交付目标为可运行原型时必须真实实现并验证导航、表单、状态联动；只有静态图片时不得声称原型完成。
- 必须区分模拟数据、真实接口、未实现行为，不得把原型演示当作后端验收。
- sdkit-ui-design 负责交互定义、视觉约束和设计复核；Foundry 负责产品文档、原型源码归档、版本、Git 与发布，具体代码实现由目标技术栈 Skill 执行。
- 原型源码与设计图片必须分别标识 artifact_type；禁止将静态 PNG 归档工具用于可运行源码的构建或发布。
- 涉及部署、PR 合并或存储写入必须另行取得授权。

正向形态：点击报名 → 校验 → 提交中 → 待审核/失败恢复；浏览器中逐项验证。反例：展示四张流程截图后宣称按钮已可点击。

## 完成标准

交互状态与可运行证据分别可核验，未验证的操作明确列出；Foundry 与开发 Skill 职责不发生重叠。
