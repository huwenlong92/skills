# 设计到开发交接

适用范围：将 UI 设计稿交给 Codex 或其他开发 Agent 实现时读取。涉及实际图片保存必须同时读取 [设计基线归档](baseline.md)。

- 必须明确 implementationMode：production、prototype 或 undecided；未决定时只归档，不自行选择开发路径。
- 必须提供项目/模块、稳定页面 ID、设计来源与修订、关键交互、桌面与移动端要求、素材、已确认与待确认、技术边界及可执行验收条件；缺失内容标记待确认。
- 必须区分已核验的现有设计图、仅文字描述、当前图片工具成功生成且产物可访问三种来源。ChatGPT Web 中图片存在不代表本地 Codex 可读取字节；不能读取时不得声称已归档。
- 具备写入授权且开始基于图片开发前，必须依 [设计基线归档](baseline.md) 完成保存、哈希及读回核验；无权限、仓库身份不明或图片不可读时停止归档与依赖该图片的实现，报告 BLOCKED。
- production：先读 AGENTS.md、适用技术栈 Skill、真实组件/API/权限，制定实现计划、类型/构建/交互与视觉验收；不得根据图片虚构后端。
- prototype：先读 Foundry 与项目原型规范，明确模拟数据、页面导航、弹窗、表单、状态及响应式；原型发布需另行授权。
- 交接文档只能放在已核验的项目设计目录；已立项归项目仓库，未立项由 Foundry 解析临时位置。不得猜测源码路径或创建固定目录树。
- 设计基线发生实质变化必须创建修订；设计版本、交接版本、原型版本、代码 Commit 与 Content Engine Release 不得混淆。
- 工程计划与偏差控制遵守目标仓库及 Development Execution；原型迁移、Git 提交和发布遵守对应规范，本 Skill 不复制其实现。

正向形态：已核验图片 SHA-256、Design ID/Revision、页面与状态、模式、验收项，并先保存再开发。反例：只说“照图实现”，没有原始资源和版本证据。

## 完成标准

开发 Agent 能定位已保存基线、实现模式与验收条件；无法定位时明确阻塞，不能用近似重绘替代。
