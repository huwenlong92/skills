# 设计到开发交接

适用范围：将 UI 设计稿交给 Codex 或其他开发 Agent 实现时读取。

- 必须声明交付目标是独立交互原型还是正式前端；不能因为存在设计图片就强制先开发 HTML 原型。
- 必须标记 `implementationMode` 为 `production`、`prototype` 或 `undecided`；未确认开发路径时只交付设计与记录。原型源码和发布由 Foundry 及目标仓库管理，正式业务由目标技术栈 Skill 实现。
- 必须提供设计来源与版本状态、目标项目/模块、含稳定页面 ID 的页面清单、关键交互状态、桌面与移动端要求、素材来源、已确认需求、待确认事项、技术实现边界和可执行验收条件；未提供的内容必须标记缺失，不得猜测。
- 必须区分三种设计来源：已有设计稿只记录实际可访问并核验的来源与版本；仅有文字描述时必须声明“文本设计说明，尚无视觉稿”；图片工具实际生成时必须核对工具成功结果和产物可访问性后才声明已生成。工具不可用、失败或产物不可访问时必须停止图片交付声明，仍可提供标记清楚的文字交接。
- 交接文件仅允许放在目标项目规范指定或用户明确授权的设计/文档位置；禁止猜测源码路径、创建固定目录树或把交接写进业务代码、凭据和部署配置。未确定位置时必须在当前回答交付说明。
- 只有已核验的资源路径、版本和哈希才能写为事实；不猜测代码仓库、原型源码目录或 Release。
- 设计会话自动归档与持续保存授权只按 [MCP 设计资产交付](mcp-delivery.md) 执行：项目唯一且授权有效时复用，歧义/切换/越界重新确认，原图不可访问时 BLOCKED；注册权限、用户保存授权及 Git 写入授权彼此独立。
- 通过 MCP 已保存的资产按 [MCP 设计资产交付](mcp-delivery.md) 交接真实 `project_id`、`page_id`、Asset ID、版本、SHA-256、Manifest 与授权读取参数；Git 未绑定时标记待交接，不冒称已写入 Git。正式开发开始前必须按项目规范核验设计身份、修订和 Git 交接记录；图片原字节可保留在 MinIO，不要求重复提交 Git。
- 已授权基于实际图片迭代或开发时，必须先按 [Git 设计交接](git-handoff.md) 完成基线保存与读回；只读讨论禁止写入。无权限、身份不明或图片不可读时必须报告 BLOCKED，并停止依赖该图的实现，禁止近似重绘代替原始证据。
- 简单修改仅提供最小变更说明；新页面需补充交互与响应式；完整新产品可按需增加页面、交互、素材、验收分文档，但不得创建空文件凑结构。
- 交接给开发 Agent 时要求先读取项目 AGENTS.md、技术栈 Skill 与既有组件，仅当目标项目提供 Development Execution 协议时要求按该协议制定计划；否则遵循项目实际工程计划规则。必要工程规范无法读取时必须停止受影响的实现操作，仍可交付标明缺失项的设计说明；sdkit-ui-design 不替代工程计划管理。
- 已确认设计基线发生实质变化时必须明确修订，不允许 Codex 自行改变产品业务流程或将示例数据当成真实数据。
- 原型源码迁移、Git 提交、R2 发布和部署遵守 Foundry/目标仓库的实际规范，不在本 Skill 中复制发布协议。

正向形态：提供设计参考、页面 ID、操作状态、素材清单、可验证验收项，并标注未决业务规则。反例：仅说“照图实现，其他自己发挥”。

## 完成标准

开发 Agent 能确定目标产物、设计来源、实现范围、关键状态与验收方式；无法定位的资源明确标记阻塞。
