# 交互与状态设计

适用范围：设计页面流程、导航、弹窗、表单、筛选、错误和反馈时读取。

- 必须列出用户关键动作及其结果；设计图未表达的业务规则不得自行确认。
- 每个关键页面按需要覆盖默认、加载、空结果、失败、成功及无权限状态；不适用的状态须说明原因，不生成无意义的空页面。
- 页面 ID、名称、导航目的地必须保持稳定；若涉及宿主与 iframe 消息、跨 Origin 通信或版本切换，只描述需求并引用目标运行系统的实际协议，禁止自创已实现的消息 API。
- 交互必须区分前端模拟、真实 API 和尚未实现的能力；原型演示不等于后端已开发。
- 涉及破坏性操作、权限或不可逆业务状态时，必须在设计中明确确认与失败反馈，不把界面确认当成真实操作授权。

正向形态：点击“保存”→输入校验→提交中→成功提示/错误恢复。反例：设计按钮但没有动作、异常与禁用状态。

## 完成标准

关键用户流程有可读的动作—状态—结果说明，所有未确认业务规则被标记为待确认。
