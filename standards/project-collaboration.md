# SDKit 跨项目协作规范

本规范适用于采用 SDKit 协作约定的任意技术栈项目。目标是让 ChatGPT、Codex、Claude 等 Agent 在跨会话、跨工具、并行 PR 开发时读取同一份可核验的项目状态。

## 规范入口与目录

项目根目录必须维护 `AGENTS.md`，用于标识仓库职责、适用 Skill、协作门禁及本规范入口。项目协作元数据统一放在仓库根目录 `.sdkit/`，必须提交版本控制，不得放在 `docs/` 或 `.agents/`。正式技术文档仍保留在 `docs/`。

```text
AGENTS.md
.sdkit/
  STATUS.md
  TASKS.md
  DECISIONS.md
  HANDOFF.md
docs/
```

- `STATUS.md`：已验证的当前状态、环境、阶段、阻塞、下一步。必须区分代码提交、CI、部署、浏览器验收。
- `TASKS.md`：任务、状态、优先级、负责分支/PR、依赖和验收条件。不得把计划标记为已完成。
- `DECISIONS.md`：重大决策、理由、替代方案、日期和影响范围。尚未确认的方案必须标注草案。
- `HANDOFF.md`：上一次任务交接，包括最后核验时间、提交/PR、未完成工作、下一步及风险。不得把它当作比 GitHub 更新的事实源。

`AGENTS.md` 必须保留与本规范一致的恢复入口，但不得重复复制整套规则；项目有特定要求时可追加，不得覆盖本规范的事实校验和安全门禁。

## 任务恢复与执行

1. 新会话先读取目标仓库 `AGENTS.md`、`.sdkit/STATUS.md`、`.sdkit/HANDOFF.md`，再核验实际代码、PR、CI 和部署状态。
2. 根据任务读取最新技术或业务 Skill。协作规范不替代 `foundry`、`wikiops`、`nuxtjs`、`sdkitgo` 等 Skill。
3. 开始修改前读取 `.sdkit/TASKS.md` 并核对文件所有权；重大决策还需读取 `.sdkit/DECISIONS.md`。
4. 只有已确认的代码、CI、部署、线上结果才能标记为完成；状态文档与实时证据冲突时，先核验并纠正状态。
5. 修改完成后按任务影响更新状态和交接；仅讨论、检索或没有实质状态变化时，不要求产生提交。

## 多会话、PR 与权限

- 并行会话必须以分支、PR 和文件修改范围区分任务，禁止未经协调覆盖其他会话正在修改的文件。
- 修改 `main`、合并 PR、发布内容、部署或切换正式域名，必须遵守目标仓库现有授权门禁。
- 未经授权不得为了更新状态文件而触发生产发布。
- 状态文件不得包含密钥、Token、Cookie、个人本机绝对路径或敏感业务数据。
- `.sdkit/` 不是 Agent 插件目录；不得将可执行插件、Skill 安装产物或临时日志写入其中。
- 项目级 Codex Skill 仍可使用 `.agents/skills/`，两者职责不重叠。

## 完成标准

- 四个文件均存在，且引用的分支、PR、仓库和部署状态已核验或明确标注待核验。
- 根目录 `AGENTS.md` 能指引新会话找到 `.sdkit/` 和适用 Skill。
- 未改动业务协议、依赖、生产配置或正式站点。
- 文档引用无失效相对路径，且不存在敏感凭据或个人本机绝对路径。
