# Development Execution V1

适用范围：多阶段、跨模块、跨会话或高风险开发任务的计划约束、阶段验收、偏差处理和恢复。普通小改动允许轻量检查，不得为此建立第二套任务数据库。

## 事实源

- 目标仓库 AGENTS.md 和适用 Skill 是实现规范；`.sdkit/TASKS.md` 记录任务状态，`.sdkit/DECISIONS.md` 记录已确认决策，`.sdkit/STATUS.md` 记录已验证事实，`.sdkit/HANDOFF.md` 记录交接。
- 复杂任务允许在 `.sdkit/plans/<task-id>.md` 保存执行契约，TASKS.md 只保留任务 ID、状态、负责分支及计划链接，不重复维护阶段状态。
- Git Commit、PR、测试输出是执行证据；计划和交接文档不能替代实际核验。
- Plan Baseline 是经确认的目标、范围与架构约束，不是 Git 锁或文件锁。

## 计划契约

复杂任务必须记录：稳定任务 ID、目标、原始 Git 基线 SHA、计划修订号、已确认决策、允许和禁止的修改范围、命中 Skill 与 references、阶段依赖、每阶段验收标准、变更审批条件和恢复入口。

- 初始基线 SHA 只记录一次；正常提交更新执行进度，不重写原始基线。
- 允许范围应覆盖必要测试与配置文件；新增文件是否越界以路径和语义共同判断。
- 未确认方案标记草案，不得伪称已批准；用户仅授权讨论时禁止写入仓库。
- 简单任务可在当前任务上下文维护轻量计划，不强制创建计划文件。

## 四个检查点

- C0 Start：开始或恢复前读取计划、决策、命中 Skill 和工作区状态；必要时核验远端。
- C1 Stage：阶段结束核对修改文件范围、架构规范、依赖变更、定向测试及未完成条件；失败不得标记 verified。
- C2 Integration：Commit/Push/PR 前按操作要求检查 Git 变更、相关 PR、兼容性和授权；Push/合并前重新核验远端。
- C3 Finish：逐条核对最终验收、测试证据、Git 交付状态和 HANDOFF；不得以编译通过代替规范验收。

简单任务允许合并 C1/C3；未发生集成操作时不强制执行 C2。禁止为了阶段检查主动触发高成本 CI 或部署。

## 偏差分级与处理

- D0：在已批准范围内调整实现细节，允许继续并在阶段记录。
- D1：范围内 Bug、遗漏测试或规范不符，先修复再重新验收。
- D2：需要新增未授权模块、升级无关依赖或扩大范围，暂停受影响修改，提交变更提案。
- D3：需要改变已确认架构、数据库策略、仓库边界或安全规则，必须先取得明确批准。

变更提案必须说明原计划、偏差原因、影响文件、风险、替代方案及新验收条件。批准后增加计划 revision 并保留历史，不得悄悄重写原决策。用户当前明确的新指令可以作为变更授权，但仍须核对目标和范围。

## 规范持续校验

- 修改前读取本阶段命中的 Skill references；阶段结束再次核对相关规则，不能仅运行格式化或编译测试。
- 静态检查覆盖文件路径、依赖锁文件、目录和测试；语义检查覆盖职责分层、业务边界、接口兼容与决策。
- 发现新技术领域或 Skill 更新时重新解析命中规范，不必每次编辑重复读取全部 Skill。
- 不得自动以 ours/theirs、reset --hard、force push 或清理未知工作区消除偏差。

## 中断恢复

1. 读取 AGENTS.md、TASKS.md、计划、DECISIONS.md 和 HANDOFF.md。
2. 核对实际 Git 工作区、分支、Commit、相关 PR 和必要测试证据。
3. 区分 planned、in_progress、implemented、verified、blocked；verified 仅代表阶段验收，不代表合并或部署。
4. 未提交修改必须保留；从第一个未验收阶段继续，不能重复覆盖已完成内容。
5. 证据不足时标记待验证，不得仅凭交接文档认定完成。

## 团队并发

任务 ID、负责分支、依赖和 PR 记录在现有项目协作文件中。不同开发者可并行；同文件和接口依赖必须执行 [跨会话协作感知](collaboration-awareness.md)。TASKS.md 不是实时文件锁；禁止建立第二套全局任务数据库。

## 完成标准

长任务中每阶段可追溯目标、修改范围、命中规范、测试证据和偏差处理；中断恢复不覆盖未知修改；D2/D3 不未经批准扩大范围；完成报告区分代码、测试、Git、CI、部署的真实状态。实际 Agent 长任务试点通过前，不得宣称防漂移已验证。
