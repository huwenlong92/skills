# Project Skill Bootstrap V1

适用范围：使用已安装的 SDKit Skill 进入业务项目开发时，检查并在明确的项目文件写入授权下安全补齐项目 `AGENTS.md` 的 Skill 入口与工程协议引用。本规范不创建新 Skill，不修改业务代码，不替代项目的真实模板身份校验。

## 触发与授权

- 开发任务首次识别到项目缺失入口、使用旧 Skill 或缺少工程协议时，必须先执行只读检查；已确认的项目配置修改授权覆盖本次入口补齐时，才允许写入。
- 只读讨论、查询、未授权仓库、远端生产环境及身份不明项目只报告建议，不得修改文件。
- 不得自动安装、卸载或覆盖 Skill；不得将本规范视为 Git Commit、Push、PR、合并或部署授权。
- 同一任务不因每次读取 Skill 重复检查；项目入口文件或 Skill 版本发生变化时重新核验。

## 项目身份与版本证据

1. 必须读取目标项目 `AGENTS.md`、技术栈配置、锁定版本与实际模板来源；不能只凭语言、目录名或用户笼统描述推断。
2. 模板身份优先依据项目明确登记的来源和可核验 Commit；来源缺失时比对目标模板的专有结构及依赖，证据不足标记 Blocked，不自动替换。
3. `nuxtjs` → `sdbase-nuxtjs-portal` 仅当项目确实采用对应 SDBase Nuxt 模板；`rust-sdcore` → `sdkit-rust-core` 仅当实际 Cargo 依赖与 core 身份匹配。其他映射遵守 [Skill Orchestration](skill-orchestration.md)。
4. 业务项目模板版本不因新 Skill 安装或模板 main 前进而自动升级；发现代码与新规范实质不兼容时保留旧入口并报告。

## 写入位置与安全边界

- 仅允许修改目标项目根目录 `AGENTS.md` 中与 Skill/工程协议入口有关的最小内容；不存在时仅在目标根目录新建，禁止在子目录生成重复入口。
- 禁止修改业务源码、依赖、锁文件、数据库、部署配置、已有 `.sdkit/` 状态或其他开发者未提交修改。
- 不得使用指向本机绝对路径的协议链接，不得把共享协议全文复制到业务项目；应记录可解析的权威来源与版本，并通过已安装 Skill 或允许的 Git Provider 读取。
- 目标文件为符号链接、工作区有未知改动、存在冲突或无法确认写入授权时，停止写入。
- 读取现有文件的内容哈希；写入前再次比较，哈希改变则停止，禁止覆盖并发修改。
- 写入前保留可恢复的原始文件字节备份；备份不得提交到仓库，写入后校验内容、原有自定义规则及文件权限。失败时仅在目标仍是本次写入结果时恢复，不覆盖其他写入者。
- 只对明确的旧 Skill 引用进行边界化替换，禁止全局字符串替换代码块、历史决策或无关文档。
- 自动生成的入口必须可辨认且可重复执行；同样输入第二次运行不得产生文件差异。已有等价入口时不添加重复段落。

## 入口建议

项目 `AGENTS.md` 的最小新增区块应包含：项目实际模板身份及已验证版本、适用主 Skill 名称、已安装 Skill 的发现入口、共享协议权威仓库 `huwenlong92/skills` 与已核验版本，以及无法读取时停止受影响操作的降级规则。禁止声称业务项目中的相对路径能够跨仓库解析。

使用 Markdown 标记 `<!-- sdkit-skill-bootstrap:start -->` 与 `<!-- sdkit-skill-bootstrap:end -->` 管理自动生成区块；标记缺失但已有等价自定义入口时只报告，不重复添加。标记不成对或出现多组时停止。

## 检查与执行

1. Discover：读取项目身份、已安装 Skill、现有入口和写入授权。
2. Plan：输出将修改的精确文件与段落、旧新映射、证据和预期 Diff。
3. Apply：仅在授权和文件哈希未变化时执行最小补丁，保留备份。
4. Verify：检查语义、引用可达性、未授权文件零修改、重复执行无 Diff；报告是否已 Commit/Push。
5. Handoff：如存在不兼容、未知来源或冲突，报告阻塞项，不擅自升级模板或删除旧安装。

## 完成标准

正确项目可以补齐唯一入口；未知项目、未授权任务、已修改文件或不适用的旧入口必须停止；项目自定义规则和未提交代码保持原样；重复执行结果相同；不因入口补齐触发 CI、数据库或部署操作。
